# Разбор шаблона заказ-заявки на 05.09.2026

## Статус

Получен реальный Word-шаблон заказ-заявки с вымышленными примерными данными,
выделенными зеленым цветом. Исходный файл не изменяется и не сохраняется в
публичном репозитории `svarnoi-core-app`.

Рабочий обезличенный шаблон и код его заполнения относятся к существующему
модулю цен и документов `svarnoi-telegram-bot`. Этот репозиторий проверен
05.09.2026 как приватный. Основное приложение продолжает подключать бот как
отдельный модуль, в соответствии с принятой структурой этапов.

Обновление 07.09.2026: ручная передача реквизитов из Telegram отменена.
Источником данных для заказ-заявки становится заполненный блок в примечании
сделки amoCRM. Telegram-бот получает только ID сделки.

## Постоянная часть документа

- реквизиты ООО «СТО Первый-Сварной»;
- юридические формулировки заявки;
- структура разделов и таблиц;
- логотип, колонтитулы, подписи и номера страниц;
- формат A4 и исходные поля для печати.

Эти элементы не генерируются заново и не редактируются ботом.

## Поля, которые заполняет менеджер

1. ФИО заказчика.
2. Адрес заказчика.
3. Телефон заказчика.
4. Представитель заказчика, если он есть.
5. Владелец транспортного средства, если отличается от заказчика и указан.
6. Марка автомобиля.
7. Модель автомобиля.
8. VIN или номер кузова.
9. Год выпуска.
10. Регистрационный знак.
11. Перечень работ с ценами.
12. Стоимость работ.

Общая сумма прописью формируется автоматически из строки `Стоимость работ`,
поэтому отдельного поля `Прописью` в блоке amoCRM нет. Цены переносятся в
документ как прислал менеджер: генератор не меняет и не пересчитывает их.

Пустые поля не заполняются значениями из соседних строк и не восстанавливаются
по догадке. Представитель заказчика и владелец транспортного средства могут
остаться пустыми. Из значений VIN и регистрационного знака удаляется только
случайно внесенное впереди слово `Номер`; само значение сохраняется.

После строки `Список работ` бот обязан переносить каждую непустую строку без
попытки разобрать дефис или двоеточие внутри нее как поле шаблона. Блок работ
заканчивается только точной строкой общей стоимости (`Стоимость работ`,
`Итого`, `Всего` или другим явно поддерживаемым названием суммы).

## Пока остаются пустыми

В переданном примере не были заполнены или не были отмечены как переменные:

- номер заявки;
- пробег;
- срок выполнения в рабочих днях;
- даты и подписи сторон.

Эти поля нельзя автоматически заполнять по догадке. Их добавляем только после
подтверждения источника и обязательности каждого значения.

## Рабочий сценарий первого шага

1. После расчета бот создает сделку amoCRM и добавляет первое примечание с
   данными клиента и рассчитанным списком работ.
2. Следующим отдельным примечанием бот отправляет только незаполненный блок
   `Заказ-заявка` как пинг для менеджера.
3. Если автомобиль идет в работу, офис-менеджер заполняет этот блок в amoCRM.
4. Менеджер нажимает в Telegram `Заказ-заявка`.
5. Бот просит ID сделки, например `#31124467`.
6. Бот получает самое свежее обычное примечание сделки с блоком
   `Заказ-заявка:`.
7. Бот проверяет наличие обязательных полей. При нехватке данных сообщает их
   список и не формирует документ.
8. При полном наборе бот возвращает готовый `.docx`.
9. Офис-менеджер проверяет документ перед печатью или отправкой.

Доступ к чтению данных сделки через Telegram разрешается только сотрудникам и
собственникам из серверного allowlist. Секреты amoCRM и персональные данные не
сохраняются в GitHub.

## Проверка реализации

- примерные ФИО, адрес, телефон, VIN, госномер и цены удалены из рабочего шаблона;
- юридический текст и структура исходного DOCX сохранены;
- оформление возвращено к исходному дизайну переданного Word-шаблона;
- экспериментальное изменение шрифтов, размеров, отступов и заливки отклонено
  после проверки пользователем и не используется;
- проверены короткий список из двух работ и длинный список из 25 работ;
- документ открывается в Microsoft Word без восстановления;
- короткий вариант занимает 2 страницы, длинный — 3 страницы;
- визуально проверены все страницы обоих вариантов;
- автоматические тесты модуля: 81 из 81 успешно.

## Следующий вход

Нужны два отдельных реальных шаблона:

1. акт выполненных работ;
2. дополнительное согласование работ.

Каждый шаблон подключается отдельным малым этапом с собственным набором полей
и визуальным тестом. Юридический текст не объединяется между документами.
