# ADR-0001: заказ-наряд как центр системы

- Статус: принято для проектирования
- Дата: 2026-07-14

## Контекст

Один автомобиль может приезжать в сервис несколько раз. В каждом визите отличаются договор, работы, фотографии, согласования, сроки и стоимость. Если строить систему вокруг автомобиля или клиента, события разных ремонтов могут смешиваться.

## Решение

Главная операционная сущность — `ServiceOrder`, соответствующая одному заказу-наряду/договору на конкретный визит автомобиля.

- Клиент может иметь несколько автомобилей.
- Автомобиль может иметь несколько исторических заказов.
- По умолчанию автомобиль имеет не более одного активного заказа.
- Номер договора — внешний бизнес-идентификатор.
- Внутренний ID — отдельный неизменяемый идентификатор.
- Фото, диагностика, оценки, дополнительные работы и события привязаны к заказу.

## Последствия

Преимущества: не смешивается история визитов, весь контекст ремонта находится вместе, согласование относится к точному заказу, а история автомобиля строится как список заказов.

Ограничение: нужно отдельно определить правило двух параллельных договоров на один автомобиль.

## Не решено этим ADR

- финансы;
- производственное планирование;
- подрядчики;
- юридическая сила электронного согласования.
