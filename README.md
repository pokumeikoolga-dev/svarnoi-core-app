# Svarnoi Core App

Единая операционная система автосервиса «Первый Сварной» с Telegram Mini App для сотрудников и клиентов.

Проект развивается поэтапно. Сначала проверяется один короткий рабочий сценарий на реальных заказах, затем добавляется следующий. Репозиторий не должен превращаться в большую ERP до подтверждения базового процесса пользователями.

## Текущий статус

- Стадия: исследование и фиксация правил.
- CRM-функции еще не реализуются.
- Первый пилот: менеджер, представитель проекта и собственник.
- Viber остается резервным каналом на период тестирования.
- Уникальный номер договора используется как внешний идентификатор заказа.
- Цены сейчас формирует существующий Telegram-бот; его нужно подключать как отдельный модуль, а не переписывать в первом этапе.

## Первый продуктовый результат

Первая проверяемая версия должна собрать в одной карточке договора:

- автомобиль и клиента;
- приемочные фотографии;
- диагностику и подготовленную оценку;
- дополнительные работы;
- статус и краткую ленту событий.

Клиентский кабинет, производственный календарь, финансы, KPI и подрядчики добавляются только отдельными этапами после проверки базовой карточки.

## Структура документации

- `.agents/` — обязательные правила для разработчиков и AI-агентов;
- `docs/product/` — границы продукта, этапы и открытые вопросы;
- `docs/research/` — подтвержденные факты о текущем процессе;
- `docs/decisions/` — архитектурные решения ADR;
- `docs/testing/` — критерии допуска этапов;
- `app/` — существующий frontend starter;
- `db/` — будущая схема данных;
- `worker/` — существующая точка входа Cloudflare Worker.

Начинать работу следует с [правил проекта](.agents/project-rules.md) и [границ первого этапа](docs/product/product-scope.md).

Предварительная модель производственной очереди описана в
[диспетчерской доске восьми подъемников](docs/product/lift-queue-and-production-dispatch-v1.md).

## Безопасность репозитория

В GitHub разрешено хранить код, правила, схемы, обезличенные примеры и историю решений.

Запрещено хранить:

- реальные телефоны и имена клиентов;
- VIN и госномера реальных автомобилей;
- договоры, счета и сканы документов;
- клиентские фотографии и переписки;
- токены Telegram, API-ключи и `.env`;
- production-выгрузки Google Sheets.

Репозиторий на момент создания документации публичный, поэтому это правило обязательно для каждого коммита.

## Технический starter

Текущая основа использует Next.js/vinext, TypeScript, Drizzle и Cloudflare bindings.

```powershell
npm.cmd install
npm.cmd run dev
npm.cmd test
```

Требуется Node.js `>=22.13.0`.
